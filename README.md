## 越权切断（只读角色补齐）

只读账号点“补齐恢复”曾会写入到达行（catchups 落行、源输出态改可写），权限页却显示只读通过。
本仓按**甲路径**切断：只读补齐在服务端拦下，正式零写入（业务库逐字节不变），并记越权审计。
甲与乙（申请单＋值班确认）互斥，本仓不实现乙；任何偏离切断卡的请求一律拒绝并记“越权偏了”。

- 补齐入口挂在**时限台补采页**，不另起越权台；登录沿用原有会话。
- 越权审计、越权锁、越权切断册落**越权专卷**，不进业务主库。
- 写越权切断卡前须封板并封档；越权当天不许改口越权切断册；不能换到乙方案。
- 只读值班与管理员同时提交同一源补齐须占越权锁，后交只记“越权补齐争用”，正式零改。
- 角色附页、越权审计列表、源目录牌、补采席队列、水位卡片与到达登记一并服务端拒写。
- 按钮置灰只是提示，不作为切断手段；真正切断在服务端。

证据与验收：

- 复现夹具：`fixtures/escalation/`（修复前 200＋写入，修复后 403＋零写入）
- 验收测试：`tests/test_escalation_cutoff.py`（只读写库失败测、双席抢补失败测）

## 为何能出多题

源时钟 vs 摄入时钟、分级处罚、降级可读不可写、补齐解冻

## 避开

别做成纯监控大盘；须有写路径与状态机

## 互斥切口候选

- 超SLA冻结 vs 降级只读
- 补齐整源解冻 vs 按业务日窗口解冻
- 只认源时钟 vs 双时钟取严
